# 피씨와 노트북이 E의 작업공간 공유 대화 정리

작성일: 2026-08-16

## 목적

PC와 노트북에서 같은 외장/공유 드라이브의 `E:\dev\codex` 폴더를 공용 Codex 작업공간으로 사용한다.

핵심은 PC와 노트북의 로컬 폴더를 서로 동기화하는 것이 아니라, 하나의 `E:\dev\codex` 작업공간을 번갈아 사용하는 것이다.

## 최종 작업공간 구조

```text
E:\dev\codex
  AGENTS.md
  피씨와 노트북이 E의 작업공간 공유
    README.md
    CHATGPT_CUSTOM_INSTRUCTIONS.md
```

보조 로컬 작업공간:

```text
C:\Users\bests\codex
```

피해야 할 작업공간:

```text
C:\Users\bests\OneDrive\Documents\ChatGPT
```

## GitHub 저장소

공용 작업공간 백업과 버전관리를 위해 GitHub 저장소를 만들었다.

```text
https://github.com/WLOC250801/codex-workspace
```

저장소는 Public이 아니라 Private으로 설정했다. 작업 메모, 설정 파일, `.env`, 토큰, 실험 코드 등이 섞일 수 있으므로 공용 작업공간 저장소는 Private으로 유지하는 것이 안전하다.

권장 연결 구조:

```text
E:\dev\codex  <->  GitHub Private repo
```

`C:\Users\bests\codex`는 로컬 보조 작업공간으로 두고, GitHub 공용 저장소에는 `E:\dev\codex`만 연결한다.

## PC와 노트북 작업 흐름

PC와 노트북은 동시에 같은 `E:\dev\codex`를 열지 않는다.

노트북에서 작업할 때:

```text
1. E 드라이브 연결
2. E:\dev\codex 열기
3. GitHub에서 pull
4. 작업 진행
5. 작업 종료 시 commit + push
6. Codex, VS Code, 터미널, 개발 서버 종료
7. E 드라이브 안전 제거
```

PC에서 작업할 때:

```text
1. E 드라이브 연결
2. E:\dev\codex 열기
3. GitHub에서 pull
4. 작업 진행
5. 작업 종료 시 commit + push
6. Codex, VS Code, 터미널, 개발 서버 종료
7. E 드라이브 안전 제거
```

요약:

```text
작업 시작 전: git pull
작업 종료 전: git add + git commit + git push
```

같은 E 드라이브를 물리적으로 옮겨 쓰더라도, 작업 시작 전 `pull`, 작업 종료 전 `push` 습관을 유지한다.

## SSD 분리 원칙

요즘 Windows는 USB 저장장치 기본 정책이 “빠른 제거”인 경우가 많아 일반 파일 저장 후에는 바로 분리해도 되는 경우가 많다.

하지만 `E:\dev\codex`는 개발 작업공간이므로 다음 상황에서는 안전 제거를 권장한다.

```text
npm install 중
git 작업 직후
개발 서버 실행 중
VS Code 또는 Codex가 프로젝트를 열고 있음
파일 복사, 압축, 빌드 중
node_modules, .venv, dist 같은 대량 파일 생성 직후
```

권장 습관:

```text
작업 종료
commit + push
프로그램 종료
E 드라이브 안전 제거
```

## Git 초기 설정 중 발생한 문제와 해결

`E:\dev\codex`에서 `git status`를 실행했을 때 다음 경고가 나왔다.

```text
fatal: detected dubious ownership in repository at 'E:/dev/codex'
'E:/dev/codex' is on a file system that does not record ownership
```

해결:

```powershell
git config --global --add safe.directory E:/dev/codex
```

외장 SSD나 일부 파일시스템에서는 소유자 정보를 Git이 확실히 확인하지 못할 수 있으므로, 해당 경로를 안전한 저장소로 등록한 것이다.

## 첫 커밋과 푸시 중 발생한 문제

처음 `git add .`를 했을 때 다음 문제가 발생했다.

```text
error: '놀이터 동영상 편집/' does not have a commit checked out
error: unable to index file
fatal: adding files failed
```

원인:

```text
E:\dev\codex 안의 일부 하위 폴더에 별도 .git 저장소 흔적이 있었음
```

해결 방향:

```text
E:\dev\codex 하나만 Git 저장소로 사용하고,
하위 프로젝트 폴더들은 일반 폴더로 관리한다.
```

필요하면 하위 폴더의 `.git`을 삭제하지 않고 `.git.backup`처럼 이름을 바꾸어 안전하게 처리한다.

최종적으로 GitHub 푸시에 성공했다.

## 일상 Git 명령 흐름

작업 시작 전:

```powershell
Set-Location E:\dev\codex
git pull
```

작업 상태 확인:

```powershell
git status
```

작업 종료 후:

```powershell
git add .
git commit -m "작업 내용 메모"
git push
```

## 자동 앱 구성

Git 작업을 쉽게 하기 위해 PowerShell 메뉴 앱을 만들었다.

### 개인용 앱

```text
codex-workspace-app.ps1
```

역할:

```text
E:\dev\codex 전용 Git 앱
```

메뉴:

```text
1. Status
2. Start work: git pull
3. Finish work: add, commit, push
4. Exit
```

사용 시점:

```text
E 드라이브 연결 직후: 2번 Start work
E 드라이브 분리 직전: 3번 Finish work
중간 확인: 1번 Status
```

`3번 Finish work`는 커밋 메시지로 아래 문구를 보여주고, `Y`를 입력해야 실행되도록 했다.

```text
Add codex workspace git app
```

### 범용 앱

```text
git-current-folder-app.ps1
run-git-current-folder-app.bat
```

역할:

```text
현재 PowerShell 위치를 대상으로 Git 작업을 수행하는 범용 앱
```

예시:

```powershell
Set-Location C:\dev\test
powershell -ExecutionPolicy Bypass -File C:\path\to\git-current-folder-app.ps1
```

이 경우 `C:\dev\test`가 대상 작업공간이 된다.

`run-git-current-folder-app.bat`는 `git-current-folder-app.ps1`을 쉽게 실행하기 위한 배치 파일이다.

두 파일은 보통 같이 둔다.

```text
git-current-folder-app.ps1
run-git-current-folder-app.bat
```

### 범용 앱 메뉴 설명

```text
1. Status
2. Start work: git pull
3. Finish work: add, commit, push
4. Initial setup: init, first commit, first push
5. Connect existing repo and first pull
6. Exit
```

각 항목 역할:

```text
1. Status
현재 폴더의 Git 상태, 브랜치, 원격 저장소, 수정 파일, 최근 커밋을 확인한다.

2. Start work: git pull
작업 시작 전에 GitHub의 최신 내용을 현재 폴더로 가져온다.

3. Finish work: add, commit, push
작업 종료 후 변경 파일을 추가하고, 커밋하고, 원격 저장소에 푸시한다.

4. Initial setup: init, first commit, first push
새 로컬 폴더를 GitHub 저장소에 처음 올릴 때 사용한다.
로컬 폴더 -> GitHub 흐름이다.

5. Connect existing repo and first pull
이미 GitHub에 있는 저장소를 현재 폴더에 처음 연결하고 가져올 때 사용한다.
GitHub -> 로컬 폴더 흐름이다.

6. Exit
앱을 종료한다.
```

일상 작업에서는 보통 아래만 사용한다.

```text
작업 시작 전: 2번
작업 종료 후: 3번
상태 확인: 1번
```

처음 설정할 때만 사용한다.

```text
새 폴더를 처음 GitHub에 올림: 4번
기존 GitHub 저장소를 처음 로컬로 가져옴: 5번
```

## 공개 가능 파일과 개인용 파일 구분

공개 가능:

```text
git-current-folder-app.ps1
run-git-current-folder-app.bat
범용 README
```

개인용:

```text
codex-workspace-app.ps1
E:\dev\codex 전용 README 내용
```

`codex-workspace-app.ps1`에는 개인 작업 경로인 `E:\dev\codex`가 고정되어 있으므로 개인용으로 두는 것이 좋다.

범용 앱은 개인 토큰이나 비밀번호가 들어 있지 않으므로 공개해도 된다. 다만 README에 개인 경로나 개인 저장소 주소가 포함되어 있지 않은지 확인한 뒤 공개한다.

## 프로젝트에 넣을 추천 위치

이 문서는 아래 위치에 넣는 것을 추천한다.

```text
E:\dev\codex\피씨와 노트북이 E의 작업공간 공유\작업기록.md
```

또는 문서 폴더를 만든다면:

```text
E:\dev\codex\피씨와 노트북이 E의 작업공간 공유\docs\codex-workspace-git-setup.md
```

## 최종 결론

`E:\dev\codex`를 PC와 노트북의 공용 작업공간으로 사용하고, GitHub Private 저장소를 백업 및 버전관리 중심으로 사용한다.

작업 시작 전에는 pull, 작업 종료 전에는 commit과 push를 수행한다.

개인용 앱 `codex-workspace-app.ps1`은 `E:\dev\codex` 전용으로 사용하고, 범용 앱 `git-current-folder-app.ps1`과 `run-git-current-folder-app.bat`는 다른 Git 프로젝트에서도 사용할 수 있다.
